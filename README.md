# Nora Bot (Нора)

Nora Bot - Telegram-бот с характером и памятью. Основные ответы генерирует Gemini 3.7 Flash, служебную логику выполняет Gemini 3.5 Flash-Lite.

## Что умеет

- Отвечает с временным контекстом, изолированным по чату, топику и собеседнику.
- Говорит голосом Норы — самостоятельной жабки-девочки, смешной болтушки и изобретательницы, а не нейтрального ассистента.
- Помнит канонический лор Норы: постоянное биографическое ядро и релевантные воспоминания о событиях.
- Ведет профили пользователей: факты, отношение, динамика общения.
- Ищет информацию в интернете (через AI-решение).
- Понимает медиа: фото, видео, документы, стикеры.
- Ставит emoji-реакции по контексту.
- При сбоях переключается на старые Flash-модели и автоматически проверяет восстановление основной.

## Как вызвать бота

Триггер в `src/config.js` уже настроен на имя «Нора» и склонения:

- `Нора`
- `Норы`
- `Норе`
- `Нору`
- `Норой`
- `Норою`

Примеры:

- `Нора, объясни эту ошибку`
- `Норе покажи свежие новости`
- `Норой что изобретём сегодня?`

## Команды

### Для всех

- `/start`, `/help` - справка.
- `/mute` - включить/выключить режим тишины в чате/топике.
- `/reset` - сброс личного диалога вызвавшего команду в текущем топике; чужая память не затрагивается.

Текстовые функции (через триггер):

- `кто я`, `расскажи про ...`
- статистика: `Нора стата` / `Нора статистика`

### Для админа

- `/banlist` - список забаненных.
- `/ban` - список последних активных для быстрого бана.
- `/ban @username|ID` - глобальный бан пользователя.
- `/unban ID` - разбан.
- `/restart` - рестарт процесса через PM2.
- `/version` - версия из `package.json`.

## Режим лички

- В личке бот полноценно работает только для `ADMIN_USER_ID`.
- Остальным пишет информационный ответ и не ведет обычный диалог.

## Установка (локально)

Требуется Node.js 20+.

```bash
git clone https://github.com/Veta-one/sych-bot.git
cd sych-bot
npm install
```

Создайте `.env` в корне проекта.

Минимально:

```ini
TELEGRAM_BOT_TOKEN=your_token
ADMIN_USER_ID=123456789
NORA_INTERVIEWER_USER_ID=123456789
AI_PROVIDER=google
GOOGLE_GEMINI_API_KEY=your_google_key
AI_MAIN_MODEL=gemini-3.7-flash
AI_LOGIC_MODEL=gemini-3.5-flash-lite
GOOGLE_NATIVE_MODEL=gemini-3.7-flash
GOOGLE_FALLBACK_MODELS=gemini-3.5-flash,gemini-2.5-flash
GOOGLE_SEARCH_MODEL=gemini-2.5-flash-lite
CONTEXT_MAX_MESSAGES=20
CONTEXT_TTL_MINUTES=30
```

Опционально для поиска:

```ini
SEARCH_PROVIDER=google
# TAVILY_API_KEY=tvly-...
PERPLEXITY_MODEL=perplexity/sonar
```

Google/Tavily/Perplexity только добывают факты. Финальную реплику с характером Норы всегда формирует основная модель.

При `AI_PROVIDER=google` сохранённый ключ OpenAI не используется для ответов или служебной логики. Дополнительные ключи Gemini задаются как `GOOGLE_GEMINI_API_KEY_2`, `_3` и далее без пропусков. Ротация отдельная для каждой модели: исчерпание квоты Lite не расходует запас основной Flash. Ключи разных проектов имеют отдельные квоты; ключи одного проекта делят квоту.

Если основная Flash недоступна, используются полноценные старые Flash-модели из `GOOGLE_FALLBACK_MODELS` по порядку: 3.5 Flash, затем 2.5 Flash. Старый `GOOGLE_FALLBACK_MODEL` поддерживается, если список не задан. Контекст, результаты поиска, картинки и личность сохраняются без изменений. Основной запрос ограничен 20 секундами, запасной — 30; при таймауте перебор остальных проектов для этой модели не продолжается. Веб-поиск остаётся на отдельной `GOOGLE_SEARCH_MODEL`: поиск текстовыми Gemini 3.x в бесплатном API недоступен. Для Gemini 2.5 нужен проект, которому эта модель ещё доступна.

После **четырёх сообщений подряд**, для которых основная модель не дала текст и запрос ушёл в резерв, бот на **четыре часа** пропускает основную. Счётчик общий для диалоговых ответов и описаний профилей во всех чатах; успешный основной ответ его обнуляет. Один ответ считается один раз, независимо от числа ключей и резервов; неудача всех резервов тоже учитывается. В этом режиме первой вызывается последняя ответившая резервная модель, а если она недоступна — остальные резервы, но не основная.

По таймеру, даже без новых сообщений в чатах, выполняется **ровно один внутренний запрос** к основной с её системным промптом. У него 30-секундный лимит, без повторов и перебора ключей. Любой непустой текст возвращает основной режим; ошибка или пустой ответ оставляет резерв ещё на час, после чего проверка повторяется. Пока проверка идёт, сообщения продолжают идти в резерв. Проверка не публикуется в чат и не попадает в диалоговую память. Состояние хранится в `data/ai-failover.json` и переживает перезапуск; суточный сброс статистики его не трогает. При изменении списка моделей старое состояние сбрасывается. «Нора стата» показывает активный резерв и время следующей проверки (UTC+5); администратор получает уведомления о переключении, продлении и восстановлении. Служебная логика и веб-поиск работают отдельно и не влияют на этот счётчик.

Используется современный Google GenAI SDK. Основная Flash работает с `thinkingLevel=low`, служебная Lite — с `minimal`; внутренние мысли в чат не отправляются. Для возвращения к OpenAI-совместимому API задайте `AI_PROVIDER=openai`, `AI_BASE_URL`, соответствующий ключ и обе модели в `.env`.

Диалоговая память хранится только в оперативной памяти процесса. Для каждой связки «чат + топик + пользователь» создаётся отдельный контекст: до 20 сообщений, каждое из которых удаляется через 30 минут. Значения можно изменить через `CONTEXT_MAX_MESSAGES` и `CONTEXT_TTL_MINUTES`. Перезапуск процесса очищает все временные диалоги.

## Канонический лор

Исходный лор бережно пересобран из [авторского документа](https://docs.google.com/document/d/1BvQG5bSnCBAIIWRrSyW3emscjIHTCgYfFG6i9NSQW0w/edit) как собственные воспоминания Норы:

- `src/lore/core.md` всегда закрепляет биографию, мир и мировоззрение;
- `src/lore/events.json` хранит отдельные события без рамки интервью и редакторских команд;
- `src/services/loreMemory.js` локально выбирает до двух относящихся к сообщению воспоминаний;
- нерелевантный лор в запрос не добавляется и внешнего API для поиска воспоминаний не требуется;
- найденное воспоминание не запускает веб-поиск по собственной биографии Норы.

Пользователь из `NORA_INTERVIEWER_USER_ID` считается давним Интервьюером Норы. Она любит и часто предпочитает так к нему обращаться, но не обязана механически вставлять обращение в каждую реплику.

По средам системный промпт включает сильную изобретательскую интерференцию: идеи Норы доходят до канонического инженерного безумия, а советы обрастают безумными изобретательскими дополнениями. Локальная `src/core/personality.js` — источник её характера и этих правил.

Запуск:

```bash
npm start
```

Или через PM2:

```bash
pm2 start src/index.js --name "nora-bot"
pm2 save
```

## Docker

### Запуск через docker compose (рекомендуется)

```bash
docker compose up -d --build
```

Контейнер:

- читает переменные из `.env`
- хранит данные в `./data` (volume `./data:/app/data`)

Остановка:

```bash
docker compose down
```

### Запуск через docker build/run

```bash
docker build -t nora-bot .
docker run -d --name nora-bot --restart unless-stopped --env-file .env -v "${PWD}/data:/app/data" nora-bot
```

## Связь с Telegram

Сетевые запросы Telegram ограничены 45 секундами. Контроль связи проверяет завершение запросов каждые 10 секунд: если 60 секунд нет ответа, получение сообщений автоматически перезапускается без перезапуска процесса и потери временной памяти. Пустые ответы Telegram тоже подтверждают исправность связи, поэтому тишина в чате не вызывает рестартов.

Администратор получает уведомления о длительном сбое и восстановлении; повторы предупреждений ограничены одним за пять минут. Если Telegram недоступен целиком, уведомление доставляется после восстановления связи. В серверном логе каждые пять минут появляется строка `[TELEGRAM HEALTH] Polling OK`.

## Хранилище данных

Бот хранит долгоживущие данные в JSON-файлах в `data/` (профили пользователей, чаты, статистика, таймер AI-резерва и т.д.). Временные диалоги туда не записываются.
Для продакшена стоит регулярно делать бэкап этой папки.

## Структура проекта

- `src/core` - логика поведения и промпты.
- `src/lore` - биографическое ядро и эпизодические воспоминания Норы.
- `src/services` - работа с AI, памятью, хранилищем и внешними API.
- `src/index.js` - запуск бота и обработка апдейтов Telegram.
